API Documentation

Authentication

All API endpoints require JWT authentication via the API Gateway.

Base URL: http://localhost:8765

Authorization Header: Bearer <token>

User ID Header: X-User-Id: <user-uuid>

🏆 Contest Service

Manages contest lifecycle, participant enrollment, and contest state transitions.

POST Create Contest
/CONTEST-SERVICE/contests/create

Creates a new quiz contest with specified parameters.

{
    "quizId": "a1b2c3d4-e5f6-7890-1234-56789abcdef0",
    "title": "Finals Week Challenge",
    "startTime": "2025-09-15T10:00:00Z",
    "endTime": "2025-09-15T11:00:00Z"

POST Join Contest
/CONTEST-SERVICE/contests/{contestId}/join

Allows an authenticated user to join a scheduled contest.

GET Get Contest Participants
/CONTEST-SERVICE/contests/{contestId}/participants

Returns a list of all participants enrolled in the contest.

Database Architecture

Each microservice maintains its own dedicated MySQL database, adhering to the "Database per Service" pattern. This ensures strong data isolation, independent scalability, and prevents a single point of failure at the database level.

Database Schemas

The system is partitioned into the following logical databases:

  • user_db: Manages user credentials, profiles, and roles.
  • question_db: Stores the entire question bank, including options and correct answers.
  • quiz_db: Contains quiz templates and structures.
  • contest_db: Manages live contest information and participant enrollment.
  • submission_db: Records user submissions and calculated scores.
🗄️

Data Isolation

Services own their data completely, communicating via APIs instead of direct database calls, which enhances resilience.

🚀

Spring Data JPA

Leverages the powerful repository pattern for efficient, boilerplate-free data access and object-relational mapping.

🔄

Transaction Management

Ensures data consistency and integrity within each service boundary with declarative, ACID-compliant transactions.

🔗

Connection Pooling

Utilizes HikariCP for high-performance database connection management, crucial for a scalable system.

Getting Started

Follow these steps to get the QuizZee platform running locally on your machine for development and testing.

Prerequisites

  • Java Development Kit (JDK) 17 or higher
  • Apache Maven 3.6+
  • MySQL Server 8.0+
  • A Git client for version control
  • Your favorite IDE (IntelliJ IDEA, VS Code, or Eclipse)

Quick Setup

# 1. Clone the repository from GitHub
git clone https://github.com/ZeeshanMalik9/Quiz-Competition-Platform--Microservices-Architecture-

# 2. Navigate to the project's root directory
cd Quiz-Competition-Platform--Microservices-Architecture-

# 3. Build all microservices using Maven
mvn clean install

# 4. Start the services in the correct order (see below)

Service Startup Order

Important: Services must be started in the following order to ensure proper registration and dependency resolution.

  1. Eureka Server (Service Registry on port 8761)
  2. API Gateway (Single Entry Point on port 8765)
  3. User Service
  4. Question Service
  5. Quiz Service
  6. Contest Service
  7. Submission Service
